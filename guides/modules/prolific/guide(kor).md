[Prolific 연결 안내](../../../PROLIFIC-SETUP(kor).md)를 따르고 `tools/prepare_prolific.py`로 외부 변경 없이 설정 자료를 준비합니다. 연구자 계정 생성·로그인, 워크스페이스 선택, URL 파라미터를 사용하는 초안 준비, 실제 연구 ID·완료 경로 확인을 안내합니다. `respondents.prolific`에 실제 검토 결과를 기록하고 검사를 통과하려고 검토 플래그를 임의로 채우지 않습니다. 기본 ID는 서명 인증이 아닙니다. 서명 URL·반복 제출 연구는 이 모듈에서 지원하지 않습니다. 연동 시험을 이유로 모집·지급을 임의로 활성화하지 않습니다.

001–004 다음에 추가 005–006을 적용하고 검토한 모델을 등록하며 일반적인 연결 시작은 원자적 `greedyq_start_prolific`을 사용합니다. 적용된 마이그레이션은 보존합니다. 철회는 답변·배정·동의 이벤트·브라우저 답변 및 순서를 한 번에 삭제한 뒤 코드·반환을 허용해야 합니다. 사전에 설명한 최소한의 관리용 식별자는 반환·중복 방지를 위해 남깁니다. 과거 철회나 이미 내보낸 복사본까지 삭제됐다고 주장하지 않습니다. 재접속, 철회 후 쓰기 거부, 동시 쓰기, 대시보드·CSV에서 답변 제거, 다른 응답 보존을 시험합니다. Native surveydown export는 삭제 기능의 차이를 공개해야 합니다.

초안 Preview 반복에는 보호된 결과 화면에서 발급한 24시간 권한과 `greedyq_start_prolific_preview`를 사용합니다. `gq_preview`는 비공개 시험 권한이며 모드 선택기가 아닙니다. 데이터베이스가 확인한 권한으로 실제 패널 ID를 유지한 채 별도 시험 공간을 만듭니다. 기본 **새 시험 시작** 버튼을 사용하고, 연구 ID 변경·참여자 ID 조작·응답 삭제·실제 중복 방지 해제를 기본 해결책으로 삼지 않습니다. 일반 새로고침은 이어가기이고 새 시험은 앞선 기록을 보존합니다. 실제 수집·만료·누락·다른 연구의 권한은 거부해야 합니다. 프로젝트 전체의 Vercel Authentication 없이 발급 API를 공개하지 않습니다.

같은 브라우저 재개, 동시 중복 차단, 테스트·실제 분리, 저장 후 코드 표시·반환, CSV ID 연결을 검사합니다. 보호된 결과 내보내기에 세 ID가 포함되며 결과를 공개할 필요가 없습니다. 가상 시험·초안 Preview·실제 Prolific 제출 중 무엇을 검증했는지 구분합니다. 기존 사전선별 확인과 별도 보상 선별을 구분해 검토합니다. 코드를 지어내거나 반환 요청만으로 실제 제출이 반환됐다고 주장하지 않습니다.

어떤 URL parameter가 participant, study, session을 식별하는지, 언제 저장할 수 있는지, 중복 참여 처리, 완료·선별 탈락·동의 거부·철회의 각 destination을 확인합니다. Completion code나 실제 return URL을 지어내지 않습니다.

필수 identifier를 검증하고 불필요하게 노출하지 않으며, consent와 data plan에 설명된 방식으로만 duplicate check를 적용합니다. 로컬 미리보기는 실제 반환을 막고 연결된 Test 전용 Prolific 초안 시험은 검토한 경로로 반환할 수 있습니다. 실제 collector 설정과 end-to-end verification에는 명시적 승인과 확인된 결과가 필요합니다.

서비스 검토/중지 상태는 설문 모드·배포 상태·응답 상태와 구분합니다. 일반 검토 메일에서 조치가 필요 없다고 하면 설정·코드·예산을 보존하고 기다리며 중복 생성·추가 충전·모드 변경·반복 게시를 하지 않습니다. `tools/prolific_status.cjs`에 보호된 결과 스냅샷과 명시적인 플랫폼 근거를 사용해 비식별 요약을 만듭니다. DB 답변만으로 유료 제출·지급을 확인할 수 없습니다. 유료 시험은 인원·실제 예상 시간·보상·표시 총액·수동/자동 검토·참여자용 동의/과제를 별도로 확인해야 합니다. 가상 종료 선택 화면을 쓰거나 거부·철회를 흉내 내도록 요구하지 않습니다. 실제 수집 주소에서 Prolific Preview를 하면 Real 기록이 생길 수 있으므로 가상 시험은 별도 Test 모델로 합니다. 답변·관리용 ID·다운로드의 보관 기한과 삭제 담당자를 확인하며 자동 보관 작업이 설정됐다고 가정하지 않습니다.

007 migration은 앞으로 저장되는 전체 답변 상태에서 빠진 답변을 같은 세션의 데이터베이스에서도 제거합니다. 조건부 문항이 숨겨져 답을 지운 경우 결과·CSV에도 남지 않아야 합니다. 다른 세션이나 과거 응답을 일괄 변경하지 않습니다. 기존 설치에는 누락된 007을 검토 후 적용하며, 로컬 소스 변경만으로 기존 운영 연구를 자동 변경하지 않습니다.

## 유료 시험 완료를 정확히 기록하기

저장·CSV 검사, 플랫폼 근거 대조, 참여 승인, 지급을 날짜·확인 주체와 함께 별도 항목으로 기록합니다. 연구자가 명시적으로 승인·지급을 확인할 수 있지만 API나 영수증을 직접 검사한 것처럼 표현하지 않습니다. 날짜별 과거 근거를 보존하고 최신 상태로 연결합니다. 완료 상태나 저장 답변만으로 지급을 판단하지 않습니다. [프로젝트의 1명 유료 시험](../../../docs/prolific-paid-test-completion-2026-10-26(kor).md)은 이를 구분하여 2026-10-26 마쳤습니다. 모든 연구자의 계정·연구를 인증한 것은 아닙니다. 008 이후 실제 종료 시각, 유료 내부 선별, 미지원인 서명·API 자동화, 보관 기한 정리를 따로 남깁니다. 기본 migration을 008까지 적용합니다. 이후 최초 종료 시각은 서버가 기록하고 재시도에도 유지하며 과거 빈칸은 그대로 둡니다. 완료한 시험을 근거로 재지급·재모집하지 않습니다.
