# 무작위 배정 구현 및 검증

[English](./randomization-verification.md)

날짜: 2026-09-10. `0.2_2026-09-10_c4a8405`를 기반으로 한 작업 폴더 변경입니다. 새 배포 버전을 발행했다거나 기존 클라우드를 업그레이드했다는 뜻은 아닙니다.

## 변경 사항

- 최소 인원 우선 배정을 독립적인 가중 단순 추첨과 무작위 고정 블록으로 교체했습니다. Python·브라우저·PostgreSQL이 같은 규약을 구현합니다.
- 승인된 페이지 내 문항 순서 섞기, 고정 위치 유지, 순서 저장, 잘못된 설정 진단, 내보내기 제한 명시를 추가했습니다.
- 서버에 등록한 연구 계획, 추가 migration 004, 미래 블록 순서 보호, 테스트/실제 분리, 실패 시 추첨 취소, 브라우저·서버 일치 확인, 순차적인 브라우저 저장을 추가했습니다.
- 결과와 아카이브에 배정 정보·문항 순서를 포함했습니다. 기준 가이드, 영문·한국어 설명서, 연결 진단, 예제 세 개, 등록부, 파일 해시를 갱신했습니다.

## 로컬 검증 근거

전체 Python 테스트는 **145개**이며 실제 PostgreSQL 연동, Python/JavaScript 파서·변환·검증 비교, SQLite 유지, 보관 및 배포 회귀 검증을 포함합니다. Node 테스트는 **23개**이며 390px·1280px의 실제 headless Chrome 조작을 포함합니다. 파일 동기화 후 최종 검사를 반복하며, 실제 Supabase 프로젝트에 대한 검증은 아닙니다.

구체적으로 시험한 상황:

- 독립적인 단순 추첨(같은 조건의 연속 배정 허용), 불균등 비율, 두세 조건, 완성된 블록의 정확한 인원, 넓은 범위의 통계적 점검.
- PostgreSQL에서 40명 동시 배정, 같은 참가자의 16개 동시 재시도, 브라우저 탭 여덟 개에서 가상 참가자 40명 공유 배정.
- 반복 브라우저 시험에서 공유 localStorage 기록이 덮어써지는 문제를 발견했습니다. HTTP 미리보기 상태를 IndexedDB transaction으로 교체하고 파일 미리보기 탭은 분리한 뒤 동시 배정을 다시 시험했습니다. Web Locks만으로 localStorage 처리가 완전히 보장된다고 가정하지 않고 실제로 수정·검증했습니다.
- 동의 전이나 필수 응답 완료 전에는 배정하지 않으며, 배정 응답 전에는 자극물을 표시하지 않음.
- 테스트/실제 배정 분리, 방식·블록·추첨 기록, 새로고침·이전 화면·재시도·프로세스 재시작.
- 철회 시 사용한 블록 자리를 재사용하지 않으며, 저장 실패 시 배정과 블록 위치를 함께 되돌림.
- 문항을 섞어도 고정 문항과 응답은 유지하고, 재방문·재접속 때 순서를 유지하며, 데이터베이스에서 순서 변경을 차단하고 삭제 요청 시 순서도 삭제.
- 이전 서버 규약 차단, 가상 연결 브라우저의 저장 순서 보장. 실제 데이터베이스 시험에는 pgcrypto, RLS/권한, 기준 SQL을 사용.
- 연구 등록 재시도·변경·이전 배정 기록 점검, 기준 파일 복사, migration 해시, 골든 연구 두 개의 배포 사전 점검.

분포 검사는 기본적인 이상 여부를 점검하며 난수 생성기의 품질을 수학적으로 증명하지는 않습니다. 정상적인 표본 변동으로 실패하지 않도록 통계 기준은 충분히 넓게 설정했습니다.

## 재실행

```sh
python3 -m unittest discover -s tests -q
node --test tests/cloud_lifecycle.cjs tests/randomization_browser.cjs
python3 -m greedyq preflight examples/complete-study
python3 -m greedyq preflight examples/simple-satisfaction-study
git diff --check
```

개발 환경에는 Python과 Node가 필요합니다. PostgreSQL 테스트는 `GREEDYQ_PG_BIN`을 사용하며 기본값은 로컬 Homebrew PostgreSQL 17 경로입니다. 비공개 임시 데이터베이스를 만들고 TCP 없이 Unix socket으로 시험한 뒤 중지합니다. 브라우저 테스트는 에이전트 환경의 Playwright와 Chrome을 사용합니다. 연구자나 참가자의 설치 요건이 아니라 개발 검증 요건입니다. 미리보기에는 최신 브라우저만 있으면 됩니다. 도구가 없어 건너뛴 테스트를 통과로 간주하면 안 됩니다.

## 남은 외부 연결 검증

이번 작업 중 기존 연구를 변경·재분류·재개·배포하지 않았습니다. 승인된 테스트 환경에서 004를 적용하고 검토한 모델을 등록한 후, 일치하는 실행 코드를 배포하여 직접 참여 테스트 완료와 CSV를 확인해야 합니다. 이전 최소 인원 우선 배정이 있는 실험은 새 연구 ID를 사용합니다. 기존 또는 공유 데이터베이스에 적용하기 전에 [업그레이드 규약](../RANDOMIZATION(kor).md)을 따릅니다. 과거 세 migration 기반의 실제 연결 검증은 당시의 검증 기록으로만 유지합니다.

응답 선택지 섞기, 페이지 전체 순서 섞기, 여러 배정 단계, 층화, 가변 블록 크기, 집단 단위 배정, 이 기능들의 Surveydown 동등성은 지원한다고 주장하지 않습니다.
