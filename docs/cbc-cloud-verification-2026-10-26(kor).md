## 범위와 리소스

이번 시험은 **가상의 Test/Direct 응답을 사용하는 v0.3 개발 검증**입니다. v0.2 기능 출시나 사람을 모집해도 된다는 승인이 아닙니다. 소유자가 이 대화에서 배포·시험을 승인했습니다. 기존 Vercel `greedyQ` 팀 연결에 `greedyq-cbc-test-survey`와 `greedyq-cbc-test-results` 프로젝트를 따로 만들었습니다. 기존 결과 프로젝트의 승인된 Supabase 연결 정보를 비공개로 재사용했으며 유료 리소스를 새로 만들지 않았습니다. 기존 Prolific 설문·결과 프로젝트는 재배포하지 않았고 지급·모집 작업도 하지 않았습니다.

- 설문: <https://greedyq-cbc-test-survey.vercel.app/>
- 보호된 결과: <https://greedyq-cbc-test-results.vercel.app/>
- 연구: `cbc_cloud_test_20261026`, `cloud-test-1`, 모드 `test`, 출처 `direct`.
- 화면: 비교 표형, 컴퓨터 가로·모바일 세로.
- 설계: 독립적으로 작성한 강의 구독 골든 예제. 블록 두 개 중 하나를 배정하고 네 과제씩 진행하며, 대안 두 개와 선택하지 않음을 제공합니다. 통계적 효율성을 보장하지 않습니다.
- 참여 안내에 소프트웨어 시험임과 철회·최소 관리 기록 보존을 명시하고 예제의 가상 문의처를 사용했습니다. 운영 수집 승인 항목은 모두 false입니다. 실제 사람을 대상으로 승인받은 동의문으로 재사용하면 안 됩니다.

## 데이터베이스 준비와 기존 자료 보존

연결된 데이터베이스에는 마이그레이션 001~008이 있었고 참여자 관련 표 일곱 개는 모두 0행이었습니다. 전체 행 수·해시를 비공개로 기록했습니다. 기존 순서와 내용을 유지한 마이그레이션에 009를 추가하여 인증서를 검증하는 TLS 연결과 기본 이력 관리 절차로 적용했습니다. 적용 전후 일곱 표의 행 수·해시가 같았습니다. 빈 기존 자료의 보존을 확인한 것이며 응답이 쌓인 운영 데이터베이스의 업그레이드 시험까지 증명하지는 않습니다.

`registerCBCStudy`로 변경 불가능한 CBC Test 계획을 등록하고 `prepareCBCDeployments`로 허용된 파일만 담은 두 게시 폴더를 만들었습니다. 공개 참여자 파일은 고정 원본과 일치했습니다. 참여자 사이트의 `registered-model.json`, 마이그레이션 SQL, 연결 파일 주소는 404였습니다. 서버 키는 보호된 결과 프로젝트의 서버 환경에만 있습니다.

## 실제 브라우저와 다운로드 검증

macOS에 설치된 headless Chrome으로 실제 Vercel/Supabase HTTPS 경로를 반복 시험했습니다. 저장이나 인증을 가상으로 대체하지 않았습니다. 컴퓨터 1280px, 모바일 390px·320px을 확인했습니다. 모바일 크기의 브라우저 시험이 실제 iOS·Android 기기 검증을 뜻하지는 않습니다.

- 동의 전에는 블록 배정·과제 노출을 만들지 않습니다. 거부하면 종료되며 선택 기록이 없습니다.
- 선택 없이 다음을 누르면 과제에 오류 안내를 표시하고 포커스를 옮깁니다.
- 선택하지 않음·이전·새로고침 후 확정한 선택과 배정된 과제 순서를 유지합니다.
- 컴퓨터·모바일 완료 시 선택과 최초 서버 완료 시각이 저장됩니다. 종료 후 새로고침해도 완료 시각이 바뀌지 않습니다.
- 보호된 결과 화면에서 비공개 24시간 Test 링크를 발급합니다. 새 시험 시작은 기존 완료 응답을 보존하고 독립적인 참여 기록을 만듭니다.
- 선택 저장 후 철회하면 응답·노출·배정·동의 기록이 삭제됩니다. 문항 순서·답변 상태도 비워지고 최소 철회 관리 기록만 남습니다. 새로고침 후에도 삭제 확인 화면을 유지합니다.
- 결과의 기본값은 실제 응답이며 가상 시험 자료는 보이지 않습니다. Test/Direct에서 시험 자료를 보이고 Prolific 필터에는 없습니다. 빈 CSV도 열 제목을 유지합니다.
- 내려받은 응답 개요·CBC 긴 CSV를 데이터베이스와 대조했습니다. PostgreSQL JSON의 정밀한 시각을 유지해 모든 긴 CSV 셀을 비교했으며 Python·브라우저 변환 결과도 같았습니다. 선택하지 않음의 속성과 미응답 선택은 빈칸이고 완료 응답의 완료 시각이 존재하며 철회·거부한 참여 기록은 선택 행을 만들지 않습니다.
- 처리되지 않은 참여자 브라우저 오류는 없었습니다.

집계와 원본 버전은 옆의 [기계 판독 기록](./cbc-cloud-verification-2026-10-26.json)에 있습니다. 소유자가 볼 수 있도록 Test 자료를 남겼습니다. 세션 접근 정보·비공개 시험 주소·자동화 인증 정보·내려받은 응답 파일·연결 파일은 저장소 밖에 보관하며 공개 증거에 넣지 않습니다.

## 결과 접근 보호 증거

결과 프로젝트의 **모든** 배포·경로에 Vercel Authentication을 적용했습니다. 로그인하지 않은 페이지·`/api/results` 요청 모두 차단됐습니다. 승인된 브라우저 시험에는 소유자가 승인한 Vercel CLI 자동화 인증을 비공개 브라우저 쿠키로 사용했습니다. 이 자동화 경로를 확인한 것이며 소유자의 별도 Safari 로그인이나 다른 팀원이 새 대시보드를 열었다는 뜻은 아닙니다. 일반 결과 주소에는 Vercel 로그인이 필요합니다. 결과를 공개하지 않았습니다.

## 에이전트의 반복 시험

`tools/verify_cbc_cloud.cjs`는 명시적으로 켜는 실제 클라우드 시험 도구이며 일반 오프라인 테스트에 포함되지 않습니다. `GREEDYQ_CBC_CLOUD_TEST=1`, 비공개 증거 폴더·연결 파일, 정확한 설문·결과 주소·연구 ID가 필요합니다. 브라우저 입력 전에 운영·패널 연구, 대상 연구의 실제 응답, Test/Direct 계획과 다른 참여자 설명을 거부합니다. 결과 화면의 연구 ID도 확인합니다. 에이전트가 승인된 결과 쿠키를 준비하며 연구자에게 비밀 키 공개나 SQL 실행을 요구하지 않습니다.

`GREEDYQ_CBC_EVIDENCE_DIR`, `GREEDYQ_CBC_ENV_FILE`, `GREEDYQ_CBC_SURVEY_URL`, `GREEDYQ_CBC_RESULTS_URL`, `GREEDYQ_CBC_STUDY_ID`를 지정합니다. 비공개 연결 파일에서 Supabase/PostgreSQL 환경 변수를 읽습니다. 에이전트 환경에 맞춰 `NODE_PATH`/`GREEDYQ_CBC_PG_MODULE`, `GREEDYQ_PYTHON`, 설치된 Chrome을 준비합니다. 도구는 가상의 세션을 추가하고 자신이 만든 철회 시험만 삭제합니다. 운영 연구 등록·모집·지급·연구 종료·관련 없는 자료 삭제는 하지 않습니다.
