# 홈페이지 프롬프트 복사 전수 검사 — 2026년 10월 26일

[English](./website-prompt-copy-audit-2026-10-26.md)

## 재현과 원인

연구자가 홈페이지 한국어 프롬프트를 제미나이·클로드에 붙여넣었을 때 줄바꿈이 사라졌습니다. `START-HERE.md`와 다음 `새 연구...`가 이어져 `START-HERE.md새`가 됐습니다. 정상 GitHub·원문 주소는 HTTP 200으로 열렸습니다. 원본 문자열에는 실제 LF 줄바꿈이 있으므로 앱 사이 복사·붙여넣기 경계의 실패이며, 저장소 비공개나 제미나이의 공개 저장소 읽기 불가를 증명하지 않습니다. 제보자의 OS 클립보드를 계측하거나 실제 Gemini 세션을 다시 시험한 것은 아니므로 서식 평탄화의 원인을 특정 앱 구현 하나로 단정하지 않습니다.

기존 표시는 줄바꿈에만 경계를 맡겼고, 일반 텍스트 Clipboard API보다 기존 `execCommand`를 먼저 사용했습니다. 취약한 가정을 제거하고 정상 줄바꿈을 유지하면서 LF가 전부 사라져도 구분되게 바꿨습니다.

## 수정한 방어

- 공통 `box`/`promptText`를 한국어 시작 화면뿐 아니라 모든 생성형 예제 프롬프트에 적용합니다. CRLF·Unicode 줄 구분·줄바꿈 없는 공백을 정규화하고 보이지 않는 zero-width/BOM 구분자를 제거합니다.
- 내부 각 행 앞뒤에 실제 ASCII 공백을 둡니다. 일반 문장의 URL을 `<...>`로 감싸 줄바꿈이 사라져도 다음 문장이 주소에 붙지 않게 합니다.
- `navigator.clipboard.writeText`를 우선합니다. 실패하면 전용 `copy` 처리기가 대체 textarea에서 `text/plain`만 기록합니다. 프롬프트를 직접 선택해 복사해도 일반 텍스트만 제공해 다른 공백 규칙을 가진 HTML 서식이 끼어들지 않게 합니다.
- 두 자동 경로가 모두 막히면 선택 영역과 수동 복사 안내를 유지하며, 실제로 복사하지 않았는데 성공했다고 알리지 않습니다.
- BibTeX는 코드로 구분해 원문·들여쓰기·중괄호를 유지하고 URL 구분 기호를 넣어 문법을 깨지 않습니다. 기존 갤러리·이미지·번역·메뉴도 유지합니다.

## 브라우저 전수 검사

`tests/website_prompt_copy.cjs`에서 영어·한국어·중국어 간체의 Start, 모든 Guide·About, 별도 Prolific, Examples를 320·1280픽셀로 방문합니다. **세 언어의 복사 블록 135개**를 두 폭에서 각각 검사해 **총 270회 정확한 복사**를 확인했습니다. 코드 블록은 폭별 6회입니다. 폭 반복 전 일반 프롬프트 132개·인용 코드 3개입니다. 270회 모두 표시된 내용과 복사된 일반 텍스트가 일치합니다. LF를 제거해도 일반 프롬프트의 URL이 구분되고 시작 주소는 정확한 값으로 남아, 해당 경계에서 `.md새`가 생기지 않습니다.

별도 검사에서 최신 클립보드 성공, 최신 경로 거부 후 대체 복사, 모든 자동 복사가 막힌 뒤 직접 선택을 세 언어에서 각각 시험했습니다. 기존 제한 iframe·수동 복사 시험도 유지했습니다. 실제 헤드리스 Chrome의 홈페이지 시험이며 Google Sites 게시나 제미나이 계정 재시험은 아닙니다.

## 게시 경계

`website/google-sites-template.html`, 언어 내용, 생성 `google-sites-embed.html`, 복사 보조 화면, 버전·히스토리 소스를 함께 준비합니다. 실제 Google Sites에는 홈페이지 워크가 새 embed를 저장·게시해야 합니다. 소스 커밋이나 HTML 생성만으로 기존 공개 화면의 복사 블록이 바뀌었다고 말하지 않습니다. 게시 후 공개 사이트의 복호화한 embed와 준비한 SHA-256을 대조하고, 새로 복사한 한국어·중국어 프롬프트를 붙여넣어 다음 문장과 주소가 분리되는지 확인합니다.
