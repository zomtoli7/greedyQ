# 반복 사용자 클라우드 여정: 검증한 동작

[English](./repeat-user-acceptance.md)

## 제품 범위

- 연구 종료: 수집 종료, 실제·테스트 CSV와 비공개 ZIP 다운로드, 보관 확인, 전용 서비스 중지.
- 잠시 중단: 수집만 닫을지 서비스까지 중지할지 선택합니다. 서비스의 **Resume project**가 수집을 재개하지는 않습니다.
- 수집 재개: 정확한 연구에 대해 별도 승인합니다. 에이전트가 미처리 데이터 요청을 확인하고 기준 재개 작업을 실행하며 기존 응답은 유지합니다.
- 다음 연구: 같은 계정을 사용하되 새 연구 ID와 전용 데이터베이스·설문·결과 프로젝트를 만듭니다. 필요하면 문항 정의를 복사하지만 과거 응답은 기본 복사하지 않습니다.
- ZIP은 보관·분석용입니다. ZIP에서 데이터베이스를 복원하는 것은 **필수 기능이나 미완료 판정 기준이 아닙니다**.

## 실서비스 인수 검사 근거

기존 `greedyq-fresh-account-test`에서 테스트 응답 2건, 답변 16개, 배정 2건의 검증된 보관 파일을 만들었습니다. 연구자가 Supabase Pause/Resume를 조작하고 에이전트가 Vercel 중지·재개를 한 뒤 일곱 테이블의 건수가 보관본과 일치했습니다. 기존·신규 응답 쓰기는 계속 차단됐고 결과 화면 로그인 보호도 유지됐습니다. Resume 직후에는 `Initializing`이어서 데이터베이스 접속 확인 후 Vercel을 재개했습니다. Resume를 누른 것을 준비 완료로 간주하지 않습니다.

그 프로젝트가 중지된 동안 같은 계정으로 서울 지역에 다음 Supabase Free 리소스를 생성했습니다. 이후 `greedyq-next-results`에 연결하고 새 `greedyq-repeat-satisfaction-test` 모델과 별도의 설문 프로젝트를 배포했습니다. 새 데이터베이스에서 기준 TLS 연결, 세 마이그레이션 적용, 반복 실행을 검증했습니다. 유료 업그레이드나 기존 데이터 가져오기는 하지 않았습니다.

새 연구에서 실제 백엔드로 세션 생성, 동의 전 저장 차단, 저장·재접속, 수집 종료, 신규·기존 쓰기 차단, 명시적 재개, 재개 후 저장, 재종료를 검증했습니다. 최종 수집 상태는 닫힘입니다. 실제 Chrome의 390px·1280px 화면에서 환영 → 동의 → 대상 확인까지 저장 오류 없이 진행했습니다. 브라우저 검사는 이 구간이며 전체 설문 완료 검사는 아닙니다. 전체 응답 저장용 백엔드 예제는 별도로 검증했습니다. 테스트 응답에는 브라우저 검사 중 미완료 건도 있으며 실제 참여자로 세지 않습니다.

- 새 설문: https://greedyq-next-survey.vercel.app
- 새 보호된 결과: https://greedyq-next-results.vercel.app
- 기존 보호된 결과: https://greedyq-fresh-results.vercel.app

인수 검사 후 두 데이터베이스는 활성 상태이고, 두 연구의 수집은 모두 닫혀 있습니다. 현재 계정 한도를 확인하지 않고 무료 자리가 더 남았다고 안내하지 않습니다. 삭제한 리소스는 없습니다. 공개 설문 파일은 열리지만 닫힌 연구에는 일반 이용 불가·저장 오류 메시지가 보일 수 있습니다. 전용 설문 종료 화면은 아직 구현되지 않았습니다.

## 기준 운영 작업

[클라우드 운영 지침](./cloud-lifecycle(kor).md)을 따릅니다. 계정·지역·무료 요금제를 명시적으로 승인받고 재시도 전 현재 상태를 조회합니다. 런타임을 다시 작성하지 말고 `prepareDeployments`를 사용합니다. 배포 전에 결과 보호를 **모든** 배포·별칭에 적용하고 비로그인 차단과 인증 API 조회를 함께 확인합니다.

수집 재개에는 `node tools/archive_study.cjs reopen PRIVATE_CONFIG.json`을 사용합니다. snapshot과 같은 검증된 `studyId`, `approvedStudyId`, `model`, `targets`, 비공개 데이터베이스 환경을 사용하되 별도 연구자 결정 후에만 `"approveReopen": true`를 추가합니다. Supabase를 먼저 Resume하고 연결을 확인한 뒤 Vercel을 재개합니다. 수집은 명시적으로 요청할 때만 재개합니다. 기존 보관본은 과거 시점의 사본이며 추가 수집 후에는 새 보관본을 만듭니다.

이번 계정에서는 Supabase Marketplace 생성 권한에 관리용 중지·재개 권한이 포함되지 않았습니다. 따라서 **연구자가 Supabase Pause project / Resume project를 조작하는 여정**을 검증한 것이며, 로그인 한 번으로 무인 자동화된 것은 아닙니다. 승인 경계를 명확히 안내하고 채팅으로 비밀키를 요청하거나 삭제로 대체하지 않습니다. Vercel 중지·재개는 범위가 지정된 CLI/API로 자동화합니다. 향후 승인된 관리 연결은 기존 중지 어댑터를 사용할 수 있지만 이번에 그 권한이 있었다고 설명하지 않습니다.
