# greedyQ v0.3 CBC 명세 초안

[English](./spec.md)

**초안 계약 `0.3-draft.1`; 가져오기·로컬 미리보기 모델 `0.3-preview.1`을 v0.2 설문 런타임과 별도로 구현했습니다.** 별도의 `0.3-collection.1` 묶음과 `cbc-1` 서버 계약으로 동의·배정·저장·철회·결과·보관을 구현하고 로컬에서 검증했습니다. 아래 MUST/SHOULD에는 혼합 작성·클라우드 승인 시험·모집·네이티브 내보내기 요구사항도 남아 있습니다. 현재 범위·명령: [CBC 미리보기](../../../CBC(kor).md).

## 오브젝트와 범위

`greedyQCBC`는 선택 기능 모듈에 들어가는 정규화된 설계 자료입니다. 연구는 기존 프로필을 유지하고 survey.qmd의 sd_cbc 표시로 태스크 시퀀스를 삽입합니다. 일반 문항은 그대로 두며 사전/사후 설문을 별도로 만들도록 요구하지 않습니다. 기본 인터뷰·윤리·승인·버전·미리보기·배포·결과 계약을 재사용하고 대체 HTML을 생성하지 않습니다. 기능별 검증·미지원 내보내기 보고를 통과한 범위만 기능 모듈로 제공합니다.

첫 범위는 모든 속성을 표시하는 무표지 단일 선택 과제, 일정한 일반 대안 수, 선택적인 “선택하지 않음”, 유한한 설계표 가져오기, 참여자당 블록 하나, 세션별 과제·대안 순서 섞기, 분석용 긴 형태 내보내기입니다. 과제 앞뒤에 일반 문항을 둘 수 있습니다.

적응형 CBC, 대안별 속성·부분 프로파일, 이중 응답 none, 최선–최악 선택, 평정형 컨조인트, 자동 효용 추정·WTP·모집단 예측·효율 설계 최적화는 후속 범위입니다. 임의 스크립트로 미지원 기능을 대신하지 않습니다.

## 필수 대화와 승인

1. 연구 질문과 대상을 확인한 뒤 AI 협업, 빈 CSV·XLSX 직접 작성, 기존 설계표 가져오기 중 어느 경로를 원하는지 묻고 기록합니다.
2. 속성·수준 문구와 단위, 과제당 대안 수, 참여자당 과제 수, 선택하지 않음의 의미, 블록과 순서 규칙을 확인합니다. 한 번에 하나의 핵심 질문을 하고 연구 방법을 임의로 정하지 않습니다.
3. 속성 확정 전에는 범용 빈 표를 제공할 수 있습니다. 확정 후에는 속성에 맞는 열을 제공합니다. `awaiting_design_table` 상태, 필요한 파일과 미결정을 저장해 다른 호스트에서도 다운로드·반환·이어가기가 가능해야 합니다.
4. 반환된 파일은 데이터로 읽습니다. 해석한 속성·수준·블록·과제 예시와 오류를 쉬운 말로 보여줍니다. 열 연결·코드 변경·행 삭제·알 수 없는 수준·설계 변경은 연구자 확인이 필요합니다.
5. 윤리·동의 결정 시점은 기본 가이드를 따릅니다. 실제 수집 전에는 동의·개인정보·승인 사항을 해결하며 AI가 제안한 과제는 초안입니다.
6. 승인한 정규화 설계와 hash를 고정합니다. 중요한 변경에는 새 설계 버전과 재승인이 필요하며 기존 참여자가 있는 등록 연구를 조용히 바꾸지 않습니다.

## 파일 계약

CSV는 UTF-8이며 BOM을 허용하고 첫 행은 열 이름입니다. ID는 문자열입니다. `001`을 `1`로 바꾸거나 번역하지 않으며 코드 공백·병합·빠진 수준을 임의로 추측하지 않습니다. 완전히 빈 행은 무시하지만 일부만 작성된 행은 오류입니다. 중복·알 수 없는 열과 표 밖의 데이터를 거부합니다. 표시 문구는 HTML에서 안전하게 처리하고 표 내보내기에서도 수식 실행을 방지합니다.

`attributes.csv`의 열은 `attribute_id,attribute_label,level_id,level_label`이며 수준 하나가 한 행입니다. 각 속성은 고유하고 안정적인 ID, 일관된 이름, 서로 다른 수준 ID 두 개 이상을 가집니다. 문구는 승인된 참여자 언어로 작성합니다. 단위는 확정된 문구·설명표에 넣습니다. 숫자 코딩은 별도 연구자 결정이며 문구에서 추측하지 않습니다.

`design.csv`의 열은 `block_id,task_id,alternative_id,<attribute_id>...`이며 선언한 속성마다 수준 코드 열이 하나씩 있어야 합니다. 한 행은 한 블록의 한 과제에 있는 일반 대안 하나입니다. `(block_id,task_id,alternative_id)`는 고유합니다. 과제 ID는 다른 블록에서, 대안 ID는 다른 과제에서 반복될 수 있습니다. 일반 대안 수는 일정하며 각 칸은 해당 속성의 수준을 가리킵니다. 후속 확장에서 명시적으로 다루기 전에는 같은 과제에 동일한 일반 프로파일을 중복하지 않습니다.

범용 빈 Design 시트에는 자리표시자 속성 열 네 개가 있습니다. 에이전트는 확정한 속성 ID로 열 이름을 바꾼 뒤 해석해야 합니다. 속성이 더 적거나 많으면 맞는 표를 제공하며 숨겨진 미사용 열을 두지 않습니다. 빈 템플릿은 `awaiting_input`이며 실행 가능한 설계가 아닙니다.

XLSX의 시트 이름은 `Attributes`와 `Design`이며 첫 행의 열 계약이 CSV와 같습니다. 서식만 있는 빈 칸은 무시합니다. 수식·저장된 수식 계산값·매크로·외부 링크는 실행하지 않고 값만 있는 파일을 요청합니다. 파일에 비밀키나 참여자 기록을 넣지 않습니다. 고정 미리보기 가져오기 코드에서 브라우저 XLSX 읽기를 구현했습니다. 제공하는 XLSX는 여전히 빈 입력 표이며 승인된 설계가 아닙니다.

## 설계 확인과 출처

표 형태·코드·빈칸·중복 키와 프로파일·과제와 블록 크기·수준·연구자가 정한 금지 조합을 확인합니다. 수준 빈도와 겹침을 진단으로 보여줄 수 있지만 파일을 읽었다거나 LLM이 제안했다는 이유만으로 균형·식별 가능성·직교성·D효율성을 주장하지 않습니다. 확정한 분석과 설계 전략에 맞는 통계적 근거가 필요합니다.

원본 파일·SHA-256·수동/외부 도구/AI 협업 출처·알려진 도구 버전과 설정·열 연결 결정·승인한 정규화 데이터를 보존합니다. 정규화 JSON은 객체 키 정렬, UTF-8, 불필요한 공백 없음, 원래 순서를 유지한 배열과 문자열 ID를 기준으로 hash를 계산합니다. 원본 파일 hash는 별도로 기록하고 정규화 과정에서 원본을 덮어쓰지 않습니다. 실제 결정론적 생성기가 지원할 때만 seed를 기록하며 임의로 만들지 않습니다.

외부 설계 도구는 다른 형식·예약 코드를 사용할 수 있습니다. 명시적으로 연결 규칙을 확인해야 하며 이 형식이 Sawtooth·Qualtrics·Ngene를 직접 호환한다고 주장하지 않습니다.

## 배정과 표시

블록 배정·과제 순서·대안 순서는 서로 다른 결정이며 각각 확인합니다. 실제 수집에서는 동의 뒤 서버가 블록을 한 번 배정하고 재시도·재접속에서도 유지합니다. 참여자는 그 블록의 과제만 받습니다. v0.2 실험 조건 배정이 그대로 CBC 블록 API인 것은 아닙니다.

자극 표시 전에 과제·대안 표시 순서를 저장합니다. 선택값은 왼쪽·오른쪽 위치가 아니라 안정적인 대안 ID입니다. 입력·이전 이동·새로고침·호스트 대화 재개로 다시 섞지 않습니다. 첫 범위의 “선택하지 않음”은 예약 ID `none`, 확인한 문구, 마지막 고정 위치를 사용합니다. 별도 설정이며 수준을 꾸민 가상 프로파일 행이 아닙니다.

컴퓨터에서는 속성 행과 대안 열을 정렬하고 읽을 수 있는 줄바꿈과 단일 선택을 제공합니다. 모바일에서는 비교할 수 있는 간결한 표 또는 승인된 세로 배치를 사용하고 속성 이름을 필요에 따라 반복하며 페이지 가로 스크롤을 피합니다. opt-out은 별도로 보입니다. 키보드·라디오 의미, 이름 붙은 과제 그룹, 이해 가능한 진행 표시가 필요합니다. 오류 시 기본 계약대로 첫 문제 과제에 초점을 옮기고 바로 위에 안내합니다. 참여자용 바로가기로 다른 블록의 자극을 드러내지 않습니다. 연구자 미리보기에서는 가상 자료로 모든 블록을 볼 수 있습니다.

## 저장과 내보내기

설계 행·배정된 표시·선택값을 구분합니다. 제안하는 표시 기록에는 연구·설계 버전과 hash, 세션, 블록, 과제, 과제·대안 위치, 표시·답변 시각, 선택 ID를 포함합니다. 서버가 배정·표시 기록을 확정하기 전에는 실제 제시로 간주하지 않으며 통신 실패로 노출·완료를 꾸미지 않습니다. 예정·표시·응답은 다른 상태입니다.

긴 형태의 내보내기는 실제 표시된 과제의 대안마다 한 행이며 none을 제공했다면 그 행도 포함합니다. 안정적 키·실제 위치·수준 코드와 문구 또는 버전 설명표·설계 hash·`chosen`을 넣습니다. 답한 과제마다 `chosen=1`은 정확히 하나이고 나머지는 `0`입니다. 미응답은 선택값을 비워 두며 none으로 추정하지 않습니다. 보여주지 않은 과제를 관측 응답처럼 내보내지 않습니다. 동의·거부·철회 상태를 별도로 설명하고 시험·실제·유입 구분을 유지합니다.

철회 시 기본 정책에 따라 CBC 선택과 개인별 표시·순서 기록을 삭제하고 사전 안내한 최소 관리 ID만 유지합니다. 009에 CBC RPC를 추가하고 기존 참여자 자료 7개 표를 재사용합니다. 보관에서 누락되는 별도 노출 표를 만들지 않습니다. 설계표를 가져왔다는 이유만으로 수집을 승인하거나 미결정 윤리·표본·분석 결정을 충족한 것으로 보지 않습니다.

## 골든 예제와 출시 기준

[온라인 강좌 요금제 예제](./golden-reference/README(kor).md)에 독립 작성한 표, 블록 계획, 가상 긴 형태 데이터와 승인 시험 시나리오를 제공합니다. 크기는 프로그램 예시이며 표본 수 권고나 통계 최적 설계가 아닙니다.

CBC를 사용 가능하다고 하기 전에 잘못된 가져오기, 빈·부분 반환, 여러 언어 문구, 문자열 ID, 금지 조합, 두 블록, 순서 유지, none과 미응답 구분, 이전·새로고침·통신 실패, 동시 저장, 철회 삭제, 보호된 결과, 긴 CSV 연결, 수정·복제와 v0.2 회귀를 시험합니다. Python·브라우저 정규화 결과가 같아야 합니다. Native Surveydown은 별도 custom control 구현과 의미 검증 전까지 CBC를 미지원으로 보고해야 합니다. 일반 객관식으로 평탄화하고 동등하다고 주장하지 않습니다.

## 모듈 구조 정정

CBC는 Simple·Experiment와 나란한 별도 연구 유형이 아니라 기존 설문에 삽입하는 선택 기능 모듈입니다. greedyQCBC는 모듈의 설계 자료 이름입니다. 일반 문항은 survey.qmd에 유지하고 sd_cbc 표시로 시퀀스 하나를 삽입합니다. 사전/사후 설문을 별도 작성하도록 요구하지 않습니다. 첫 규약은 선형 주변 페이지를 지원하며 페이지 분기·일반 선택지 셔플·복수 CBC는 명시적으로 거부합니다.
