## 연구자의 시작 선택

연구 주제를 확인한 뒤 “사람들이 비교할 조합을 어떤 방식으로 준비할까요?”라고 먼저 묻고 세 가지 경로를 제시합니다.

1. AI와 대화하며 속성·수준·선택 과제를 제안받고 검토하기.
2. 빈 CSV 또는 Excel 파일을 받아 직접 채운 뒤 돌려주기.
3. 다른 작업에서 만든 설계표를 가져와 열 연결과 제한 조건을 검토하기.

컨조인트를 요청했다는 이유만으로 AI 생성을 선택한 것으로 간주하지 않습니다. 빈 파일을 원하면 파일과 짧은 안내를 제공하고 작업 상태를 저장한 뒤 기다립니다. 반환된 표의 빈칸을 임의로 채우거나 설계를 조용히 바꾸지 않습니다.

[빈 Excel 파일](./templates/cbc-design-template.xlsx)은 `Attributes`와 `Design` 시트로 구성됩니다. CSV는 [attributes-blank.csv](./templates/attributes-blank.csv)와 [design-blank.csv](./templates/design-blank.csv)를 함께 사용합니다. 속성 목록을 확정한 뒤에는 실제 속성 이름이 열 제목에 들어간 연구별 표를 제공하는 것이 다음 구현의 기본입니다. 범용 파일의 `attribute_1` 등은 빈 틀을 위한 자리이며 확정된 연구 속성이 아닙니다.

## 구현 순서

1–5 단계는 로컬 구현·검증을 마쳤습니다. 6 단계에는 공개 프로파일 활성화 전 신규 계정 클라우드 승인 시험·혼합 작성·네이티브 내보내기가 남아 있습니다.

1. v0.3 계약과 골든 예제를 정리하고 미결정 연구 사항을 검토합니다.
2. Python 기준 가져오기·검사 코드를 구현해 독립적으로 시험합니다.
3. 같은 규칙을 브라우저에 옮깁니다. XLSX는 고정된 기본 코드로 읽고 매크로·수식은 실행하지 않습니다.
4. CBC 표시와 컴퓨터·모바일 미리보기, 구조 보기를 구현합니다.
5. 서버에 유지되는 블록·과제·대안 순서, 동의·철회 처리, 긴 형태의 데이터 내보내기를 추가합니다.
6. 신규 생성, 표를 채워 돌아오기, 이어가기, 수정·복제, 배포·결과와 오류 사례를 시험한 뒤에만 공개 registry에서 `cbc`를 활성화합니다.

현재 [예제 검사기](../../../tools/check_cbc_reference.py)는 초안 표와 예상 가상 내보내기만 검사합니다. 실제 서비스용 가져오기 기능이 아니며 통계적 설계 효율이나 추정 결과를 주장하지 않습니다.

## 실제 수집 전에 결정할 것

가상 예제는 프로그램의 기준을 정할 뿐 실제 연구의 가설·모집단·표본 수·추정법·윤리·통계적 적절성을 확정하지 않습니다. 연구자가 명시적으로 확인하기 전에는 미결정으로 남깁니다. 부분 프로파일, 적응형 컨조인트, 최선–최악 선택, 평정형 컨조인트와 내장 추정은 첫 CBC 범위에 포함하지 않습니다.

[초안 예제 schema](./design.schema.json)는 기획 메타데이터만 검사합니다.
